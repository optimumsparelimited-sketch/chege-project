---
name: Zod import in api-server routes
description: Using zod/v4 subpath in api-server breaks the esbuild bundle step
---

**Rule:** In `artifacts/api-server/src/routes/*.ts`, always import Zod as `import { z } from 'zod'` — never `from 'zod/v4'`.

**Why:** The api-server uses esbuild to bundle to ESM. esbuild cannot resolve the `zod/v4` subpath export and fails with "Could not resolve zod/v4". The plain `zod` import works fine. Also requires `zod` to be listed in `artifacts/api-server/package.json` `dependencies` (not just transitive via api-zod).

**How to apply:** Any route file that needs Zod directly (e.g. for inline schemas not generated by Orval) must use `import { z } from 'zod'` and have zod in api-server dependencies.
